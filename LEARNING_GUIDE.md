# Как самостоятельно разобраться в HeatShield

Этот документ рассчитан на человека, который знает основы Python и хочет понять **зачем** написана каждая часть проекта. В собственных `.py` файлах рядом с кодом стоят русские комментарии. Читайте сначала этот маршрут, затем код: так отдельные строки будут складываться в понятную систему.

## Быстрый запуск

- `START_HEATSHIELD.bat` — двойной щелчок: открывает готовый EXE. Если EXE отсутствует, использует уже установленное `.venv` и запускает исходники.
- `SETUP_AND_RUN.bat` — для первого запуска исходников: создаёт `.venv`, устанавливает пакеты из `requirements.txt` и открывает приложение. Нужны Python 3.11 и интернет.
- `.venv\Scripts\python.exe -m pytest -q` — прогон проверок после ваших изменений.

Для понимания вычислений лучше запускать `main.py` из исходников: тогда можно менять строки и сразу видеть результат. Папки `.venv`, `build` и `dist` созданы внешними инструментами; изучать их файлы построчно не требуется.

## Путь одного анализа

1. `main.py` создаёт приложение Qt и открывает главное окно.
2. `ui/full_window.py` получает выбранный участок и параметры пользователя. Долгие запросы передаются в `services/background_worker.py`, чтобы окно не зависало.
3. `core/map_loader.py` получает реальные объекты OpenStreetMap. `core/city_builder.py` распределяет их по слоям: здания, дороги, велодорожки, тротуары, воду, зелень, известные деревья, запретные места и точки притяжения. `core/local_data.py` читает дополнительные GeoJSON с местными деревьями и запретными полигонами, переводит координаты в метры и добавляет объекты до расчёта кандидатов.
4. `core/geodesy.py` переводит границы участка из широты и долготы в проекцию с **метрами**. Для расстояний и площадей нельзя напрямую вычитать градусы широты.
5. `core/free_space.py` вычитает известные препятствия и их защитные отступы. Получаются предварительные точки-кандидаты. `core/audit.py` отдельно повторно проверяет расстояния до препятствий. В `tests/test_local_constraints.py` посмотрите реальные геометрические примеры тротуара, ряда деревьев и импортированного запрета.
6. `core/heat_model.py`, `core/vegetation.py` и `core/pedestrian.py` рассчитывают для кандидатов три относительные оценки. Они используют свойства территории, но не притворяются измерениями температуры или числа прохожих.
7. `core/optimizer.py` выбирает деревья с учётом бюджета и минимального расстояния. Greedy выбирает следующую точку с наибольшей дополнительной условной пользой; Random создаёт воспроизводимую базу сравнения.
8. `core/metrics.py` считает показатели обоих планов по одинаковым правилам: стоимость, площадь новых условных крон, долю путей под кроной и сценарный индекс.
9. `ui/map_widget.py` передаёт данные в `ui/assets/map.html`. JavaScript здесь нужен только для интерактивной карты Leaflet. Возврат кликов и перетаскивания в Python проходит через `ui/map_bridge.py`.
10. `services/export.py` сохраняет сценарий и карты. Папка `tests` содержит проверки отдельных правил, а `examples/almaty` — сохранённый пример на реальной территории.

## Самые важные переменные

| Имя | Что означает | Единицы |
|---|---|---|
| `lat`, `lon` | Широта и долгота для обычной карты | градусы |
| `x`, `y` | Те же точки в метрической проекции | метры |
| `bounds` | Юг, запад, север, восток участка | градусы |
| `budget`, `cost_per_tree` | Доступные деньги и цена одной посадки | тенге |
| `minimum_distance_m` | Минимальное расстояние между новыми деревьями | метры |
| `shade_m2` | Объединённая условная площадь новых крон внутри участка | м² |
| `study_area_shaded_percent` | `shade_m2 / площадь участка × 100` | % площади |
| `heat` | Относительная модельная тепловая нагрузка | без единиц |
| `pedestrian` | Относительная модельная востребованность пешеходами | без единиц |
| `green_deficit` | Относительный дефицит размеченной зелени | без единиц |
| `relative_utility` | Значение выбранной пользователем функции пользы | условные единицы |

## Как читать комментарии и проверять гипотезы

Начните с `config.py`, `core/free_space.py`, `core/optimizer.py` и `core/metrics.py`. После каждого файла откройте соответствующий тест: например, `core/optimizer.py` рядом с `tests/test_optimizer.py`. Тест показывает не только ожидаемое число, но и причину ограничения.

Попробуйте изменить **только** `heat_weight` во вкладке «Параметры», повторить оптимизацию и сравнить адреса точек, `relative_utility`, площадь тени и долю пешеходных путей. Улучшение одной оценки не гарантирует улучшение каждой метрики — приложение показывает эти показатели отдельно.

Другой полезный опыт: перетащите одно зелёное дерево к кандидату. `ui/map_bridge.py` передаст координаты в Python, `core/optimizer.py` привяжет перенос к допустимой точке и проверит расстояния, а `core/metrics.py` пересчитает показатели. Так можно увидеть полный путь данных от мыши до результата.

## Где модель честно ограничена

OSM может не содержать часть зданий, деревьев или тротуаров. Геометрически свободное место не доказывает право посадки, наличие почвы и отсутствие подземных сетей. Радиус будущей кроны и отклик условного теплового индекса — явно записанные допущения в `config.py`, а не обученная на местных наблюдениях модель. `VALIDATION.md` разбирает реальный пример и показывает, где Greedy выигрывает и где Random даёт больше тени.
